# از Pull تا تست APK و انتشار AAB/BIN

این مراحل برای علوم‌یار هفتم `0.15.2-grade7-1405` با کد نسخهٔ `19` است.

## کلید RSA بعد از Pull از کجا می‌آید؟

فایل `local.properties` مخصوص رایانهٔ شماست و در گیت ثبت نمی‌شود. لازم نیست کلید RSA داخل آن دیده شود. مسیر SDK همان رایانه، یعنی `sdk.dir`، در این فایل باقی می‌ماند.

کلید عمومی واقعی ارائه‌شده توسط صاحب برنامه و اثر انگشت آن در **`config/bazaar-grade7.properties`** ثبت شده‌اند. این فایل با Pull دریافت می‌شود. Gradle فقط از همین فایل، مقدار `BuildConfig.BAZAAR_RSA_PUBLIC_KEY` را می‌سازد. تنظیم RSA در `local.properties`، متغیر محیطی یا پارامتر قدیمی Gradle دیگر این مقدار را عوض نمی‌کند. برای به‌روزرسانی آیندهٔ کلید، همین فایل عمومی با تأیید صاحب برنامه تغییر می‌کند.

همان کلید به `SecurityCheck.Enable(rsaPublicKey = ...)` در پولکی و به بررسی‌کنندهٔ مستقل رسیدهای ذخیره‌شده می‌رسد. کلید خصوصی یا رمز امضای انتشار از RSA عمومی پرداخت قابل استخراج نیست و در مخزن قرار نمی‌گیرد.

## ۱. Pull و تأیید تنظیمات

۱. در Android Studio پروژهٔ `nranjbar/oloomyar7` و شاخهٔ `main` را باز و آخرین تغییرات را Pull کنید.

۲. Gradle Sync را کامل کنید. JDK پروژه **۱۷** است؛ SDK کامپایل **۳۷** است. فایل `local.properties` و مسیر SDK همان رایانه را نگه دارید.

۳. در `app/build.gradle.kts` نسخهٔ `0.15.2-grade7-1405` و `versionCode = 19` را ببینید. فایل `config/bazaar-grade7.properties` باید کلید واقعی و فیلد `GRADE7_BAZAAR_RSA_PUBLIC_KEY_SHA256` را داشته باشد.

۴. در Terminal ریشهٔ پروژه، در PowerShell اجرا کنید:

```powershell
.\gradlew.bat :app:verifyBazaarReleaseConfiguration
```

در macOS/Linux:

```bash
./gradlew :app:verifyBazaarReleaseConfiguration
```

خروجی موفق، این مشخصات را اعلام می‌کند:

```text
Grade 7 Bazaar configuration: PASS
Public key source: config/bazaar-grade7.properties (local RSA overrides are ignored)
Application ID: com.oloomyar.app.grade7
RSA public key: 1392 bits; SHA-256: 93a592bccda2e6302461e8a5ddf052019e0ad6ced7ae71519567514ecbcada2c
Release REVIEW_MODE=false; chapter 1 is free, chapters 2-15 require verified ownership.
```

این کنترل پیش از ساخت release نیز خودکار اجرا می‌شود. کلید خراب یا اثر انگشت نامطابق، ساخت را متوقف می‌کند. این بررسی، ساختار و استفادهٔ کلید را تأیید می‌کند؛ تراکنش واقعی حساب بازار باید جداگانه آزمایش شود.

## ۲. ابتدا APK امضاشدهٔ release بسازید

۱. **Build → Generate Signed Bundle / APK** را باز کنید.

۲. **APK** را انتخاب و **Next** را بزنید. ماژول `app` باشد.

۳. فایل **JKS انتشار خودتان**، alias و رمزهای آن را در همان پنجره انتخاب کنید. اگر این بسته قبلاً منتشر شده، از همان کلید انتشار قبلی استفاده کنید. برای اولین انتشار و در صورت نداشتن کلید، **Create new** را بزنید؛ مثلاً مسیر `C:\OloomYarKeys\oloomyar7-release.jks` و alias برابر `oloomyar7`. برای کلید تازه اعتبار دست‌کم ۲۵ سال و رمز یکسان برای مخزن و کلید طبق راهنمای Android Studio انتخاب کنید. فایل و رمزها را برای تمام به‌روزرسانی‌ها حفظ کنید.

۴. در مرحلهٔ بعد **Build variant = release** را انتخاب کنید. در صورت نمایش گزینه‌های امضا، **V1 و V2** را فعال کنید تا حداقل اندروید ۶ پروژه نیز پوشش داده شود. مقصد نمونه `C:\OloomYar7\app` است.

۵. ساخت را تمام کنید و با **Locate** فایل خروجی را پیدا کنید. در مقصد نمونه، مسیر معمول این است:

```text
C:\OloomYar7\app\release\app-release.apk
```

مسیر دقیق اعلام‌شده در Locate ملاک است. این فایل را برای تست روی گوشی یا پروفایل آزمایشی نصب کنید.

APKهای بازبینی قبلی با گواهی آزمایشی متفاوت امضا شده‌اند. APK انتشار با گواهی خودتان، روی آن‌ها به‌صورت به‌روزرسانی نصب نمی‌شود. برای حفظ پیشرفت نسخهٔ بازبینی، از گوشی یا پروفایل آزمایشی جدا استفاده کنید.

دکمهٔ Run معمولی Android Studio غالباً build نوع debug را اجرا می‌کند که فصل‌ها برای بازبینی بازند. برای آزمایش قفل و پرداخت، همین APK امضاشدهٔ **release** را نصب کنید.

## ۳. تست نسخهٔ release

| بررسی | انتظار |
| --- | --- |
| نصب تازه، پیش از خرید | فصل اول رایگان و فصل‌های ۲ تا ۱۵ قفل باشند |
| صفحهٔ خرید | محصول `oloomyar_g7_complete` و مبلغ ۱۹۵٬۰۰۰ تومان؛ در پیشخوان ۱٬۹۵۰٬۰۰۰ ریال |
| لغو یا شکست پرداخت | خرید تأییدنشده، فصل پولی را باز نکند |
| خرید موفق و تأییدشده | همهٔ فصل‌های ۲ تا ۱۵ باز شوند |
| بستن کامل و اجرای دوباره | خرید معتبر همان نصب حفظ شود |
| اجرای دوباره بدون اینترنت | فصل‌های خریداری‌شدهٔ همان نصب باز بمانند |
| به‌روزرسانی با همان امضا | خرید و پیشرفت حفظ شوند |
| نصب تازه یا گوشی دیگر | با همان حساب بازار، بازیابی خرید انجام شود |

برای تست تراکنش، بازار باید نصب باشد، کاربر وارد حساب بازار شده باشد، محصول در برنامهٔ **هفتم** فعال باشد و شرایط آزمایش پیشخوان رعایت شوند. نصب APK به‌تنهایی فعال‌بودن محصول در حساب بازار را ایجاد نمی‌کند.

## ۴. پس از تأیید APK، AAB امضاشده بسازید

دوباره **Build → Generate Signed Bundle / APK** را باز کنید؛ این بار **Android App Bundle** را انتخاب کنید. ماژول `app`، نوع `release` و **همان JKS و alias مرحلهٔ APK** را استفاده کنید.

مسیر معمول با مقصد نمونه:

```text
C:\OloomYar7\app\release\app-release.aab
```

اگر بعد از تست APK تغییری در کد دادید، APK جدید را نیز دوباره آزمایش کنید و AAB را از همان سورس نهایی بسازید. کد نسخه برای بارگذاری بعدی باید از بیشترین کد ثبت‌شدهٔ همین برنامه در پیشخوان بیشتر باشد.

## ۵. BIN همین AAB را بسازید و جفت فایل را بارگذاری کنید

فایل رسمی `bundlesigner-0.1.14.jar` را از [انتشارهای بازار](https://github.com/cafebazaar/bundle-signer/releases) دریافت کنید. در نمونهٔ زیر مسیرها را با فایل‌های خودتان تطبیق دهید و فرمان را در یک خط اجرا کنید:

```text
java -jar "C:/OloomYarTools/bundlesigner-0.1.14.jar" genbin -v --bundle "C:/OloomYar7/app/release/app-release.aab" --bin "C:/OloomYar7/release-output" --v2-signing-enabled true --v3-signing-enabled false --ks "C:/OloomYarKeys/oloomyar7-release.jks" --ks-key-alias oloomyar7
```

ابزار رمزها را درخواست می‌کند. `--bin` پوشهٔ خروجی است؛ فایل نمونه `C:\OloomYar7\release-output\app-release.bin` خواهد بود. AAB و BIN باید با همان هویت امضای APK آزمایش‌شده ساخته شوند. با هر ساخت دوبارهٔ AAB، BIN متناظر تازه تولید کنید و جفت فایل نهایی را در همان برنامهٔ پیشخوان بارگذاری کنید.

## خروجی‌های CI و امضای شخصی

CI برای بررسی ساخت، APK و AAB نوع release را **بدون امضای خصوصی صاحب برنامه** می‌سازد و کلید عمومی، بستهٔ هفتم و خاموش‌بودن حالت بازبینی را کنترل می‌کند. فایل unsigned برای نصب عادی یا بارگذاری نهایی آماده نیست. مسیر **Generate Signed Bundle / APK** خروجی امضاشدهٔ شما را می‌سازد.

وظیفه‌های `:app:prepareBazaarReleaseApk` و `:app:prepareBazaarRelease` به‌ترتیب ساخت APK و AAB را همراه با کنترل کلید اجرا می‌کنند؛ این فرمان‌ها جای انتخاب JKS شخصی در Android Studio را نمی‌گیرند.

فایل‌های JKS، keystore و تنظیمات محلی امضا در `.gitignore` قرار دارند. کلید عمومی پرداخت با Pull آماده می‌شود؛ امضای خصوصی انتشار روی رایانهٔ صاحب برنامه انجام می‌شود.

راهنمای بازار، تأیید سمت سرور را نیز توصیه می‌کند. پروژهٔ فعلی بررسی RSA و نگهداری رسید معتبر را روی دستگاه انجام می‌دهد؛ سرور پرداخت جداگانه ندارد. آزمون خرید واقعی در حساب صاحب برنامه طبق مرحلهٔ ۳ انجام می‌شود.
